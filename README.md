# Lowcal

Адаптивный дневник питания на **Next.js 16, React 19, TypeScript, Supabase и Gemini**. Интерфейс RU / UZ / EN, светлая и тёмная темы. Шрифты раздаются локально, без запросов к Google Fonts.

## Запуск

Нужен Node.js 24 (версия в `.nvmrc`). Используйте существующий checkout; для облачной задачи отдельный Git worktree не нужен.

```sh
cd /workspace/lowcal
npm ci
npm run dev
```

Без внешних ключей уже работают: настройка цели, расчёт по Миффлину — Сан Жеору, ручной ввод и собственные блюда, поиск по небольшому каталогу, изменение порций и БЖУ, избранное, дневник по датам, история веса, графики за 7 дней, CSV, локальное сохранение и удаление данных. Каталог содержит приблизительные значения, а не полный справочник продуктов. Продукты не добавляются автоматически без проверки пользователя.

Для production:

```sh
npm run build
npm start
```

Оба сервера слушают порт 3000. `NODE_USE_ENV_PROXY=1` в командах запуска включает штатный proxy для Node.js 24; TLS-проверки не отключаются. Внешние ключи не нужны для сборки.

## Supabase: вход и синхронизация

1. Создайте проект Supabase. Выполните [`supabase/schema.sql`](supabase/schema.sql) в SQL Editor. Скрипт повторно запускаемый.
2. Скопируйте `.env.example` в **неотслеживаемый** `.env.local`. Заполните публичные `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` из настроек проекта. `service_role` в браузер не передаётся и этому приложению не требуется.
3. В Authentication → URL Configuration задайте Site URL и разрешённые callback URL вида `https://ВАШ-ДОМЕН/auth/callback`. Для локальной разработки разрешите соответствующий callback на порту 3000.
4. Email provider включает вход по ссылке. Для публичной рассылки настройте SMTP в Supabase. Для Google включите Google provider и настройте Google OAuth client в консоли провайдера; callback провайдера берите из Supabase.
5. Перезапустите сервер; после изменения `NEXT_PUBLIC_*` пересоберите production, поскольку эти значения встраиваются при сборке.

После входа пустой облачный аккаунт предлагает явно перенести локальный дневник или начать отдельно. Записи каждого аккаунта хранятся отдельно. Сохранение использует номер версии: изменения с другого устройства вызывают предупреждение, а не молчаливую перезапись. При конфликте сначала экспортируйте локальные записи и затем загрузите облачную версию. При ошибке подключения редактирование облачного дневника блокируется до повторного чтения/сохранения; локальная копия сохраняется для экспорта.

RLS позволяет читать только собственные данные. Запись — через RPC с проверкой `auth.uid()`. Очистка облачного дневника удаляет его содержимое, сохраняя пустую версионированную запись, чтобы старое устройство не восстановило удалённые данные. Очистка дневника не удаляет Auth-аккаунт, историю лимитов и membership; полное удаление аккаунта выполняет оператор через Supabase Auth (зависимые строки удаляются каскадно). Выход возвращает отдельный гостевой дневник. На общем устройстве также очищайте данные сайта: браузер сохраняет локальную копию аккаунта для восстановления после сетевой ошибки.

## Gemini: текст и фотографии

Добавьте **серверный** `GEMINI_API_KEY`. Модель по умолчанию `gemini-2.5-flash`; её можно переопределить через `GEMINI_MODEL` на поддерживаемую в вашем проекте. Перезапустите сервер. В облачной среде разрешите HTTPS к `generativelanguage.googleapis.com` и hostname вашего проекта Supabase.

Нужен авторизованный Supabase-пользователь и установленная SQL-схема. `/api/analyze` проверяет same-origin, сессию, согласие на передачу данных, размер запроса и лимит из БД. Для reverse proxy при необходимости задайте `APP_ORIGIN=https://ВАШ-ДОМЕН` (без завершающего `/`). API принимает JPEG/PNG/WebP до 4 МБ и ограничивает upstream таймаутом. Ответ Gemini проверяется по схеме; значения относятся ко всей указанной порции, не к 100 г. Изображение не сохраняется в дневнике или Supabase Storage. Не отправляйте личные сведения на фото.

Лимиты запросов в сутки UTC: **Free — 5, Pro — 100, VIP — 200**. Лимит резервируется перед внешним запросом; неудачные попытки тоже учитываются для защиты расходов. Все реализованные AI-режимы используют этот лимит. Оплата и автоматические подписки не реализованы.

Голос вводится через Web Speech API при поддержке браузера и с его разрешением на микрофон, после чего пользователь отправляет текст в Gemini. Обработка голоса может выполняться внешним сервисом поставщика браузера. На некоторых устройствах и для узбекского языка поддержка ограничена; текстовый ввод всегда доступен. Распознавание еды не определяет аллергены достоверно и не является медицинским советом.

## Доступ выбранным пользователям

Сначала пользователь должен зарегистрироваться. Чтобы назначить **себя** администратором, возьмите UUID своего аккаунта из Supabase Auth и выполните только в доверенном SQL Editor:

```sql
insert into public.app_admins(user_id)
values ('ВАШ_UUID') on conflict do nothing;
```

После обновления страницы в «Настройках» появится панель выдачи Free / Pro / VIP по email с необязательным сроком. Администратор может выдавать полный VIP без оплаты. Проверка полномочий выполняется в PostgreSQL; показ/скрытие панели не служит защитой. Самостоятельное повышение прав через клиент запрещено. Прямой SQL-пример выдачи VIP также есть в конце `schema.sql`.

## Проверки

```sh
npm run typecheck
npm test
npm run build
# На обычной машине сначала: npx playwright install chromium
npm run test:e2e
# В этой облачной среде CDN Playwright недоступен; установлен Chromium из npm:
LOWCAL_USE_BUNDLED_CHROMIUM=1 npm run test:e2e
```

Unit/integration: расчёты, масштабирование порций, валидация, безопасный CSV; реальная SQL-схема исполняется в локальном PostgreSQL через PGlite с проверкой RLS, конфликтов версий, Free/VIP-лимитов и административных прав. Browser E2E: desktop/mobile, настройка цели, поиск, сохранение после перезагрузки, правка порций, избранное, RU/UZ/EN, тёмная тема, CSV, удаление, недоступность AI без ключей и защита API. SQL-тесты не заменяют end-to-end проверку на вашем Supabase-проекте; реальные OAuth, доставка писем и ответы Gemini требуют подключения сервисов.

## Границы этой версии

- Напоминания работают только пока вкладка открыта, раз в 3 часа после включения. Нет фоновых push.
- Карточка поддержки использует понятные правила дневника; это не отдельный AI-чат.
- Telegram-вход, штрихкоды, интеграции ресторанов, платежи и расширенные рецепты с расчётом по ингредиентам — следующие этапы.
- Автоматическая норма — оценка для взрослых 18–90 лет, а не «максимально точный» медицинский ответ. Данные массы и роста пользователь сообщает сам. Аллергии/предпочтения сохраняются как напоминание, не как гарантия безопасности.
- Дневник в браузере хранится в localStorage. Приложение не реализует сквозное шифрование. Supabase должен использовать HTTPS и штатное шифрование хранения проекта. Пароли приложение не хранит: вход по ссылке или Google.
- В приложении есть пояснения о данных и условиях. Перед публичным запуском нужно добавить сведения об операторе, контакты, сроки хранения, процесс полного удаления аккаунта и окончательные юридические документы. Договоры и политику хранения внешних провайдеров проверяет оператор.
- Аналитики и рекламных cookies нет; Supabase использует необходимые cookies для сессии.

Ничего не опубликовано автоматически; deployment и подключение реальных сервисов выполняются отдельно.
